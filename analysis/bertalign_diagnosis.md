# Bertalign 结果异常的根因

你这份对齐结果的主要问题不是「模型坏了」，而是**输入分段策略把中英文切成了不对称粒度**，导致动态规划路径不断“吞并/跳过”句段：

1. 中文端把标题（`# ...`）、小节名、列表项都当成独立短段。
2. 英文端很多标题和正文会被合并成较长段。
3. 大量短段（特别是标题）在语义上信息不足，容易被判为 `[]`（未对齐）。
4. 你导出的 `src_ids/tgt_ids` 出现 `np.int64(...)`，说明输出时没有彻底转原生 `int`（或使用了旧版脚本）。

## 直接表现

- 前面连续多行中文标题 `tgt_ids=[]`。
- 后面经常出现 `4->1`、`3->1` 这类大块吸附。
- 小节标题和正文被串到同一行，跨段边界模糊。

## 修复方向

- 预处理时去掉 Markdown `#` 标记，避免标题 token 干扰。
- 中英文统一：标题单独标注（如 `<H>`），正文再做句切。
- 列表项保持整条，不要按分号再切碎。
- 参数改为更保守组合（例如 `max_align=3, top_k=5, win=8`），减少过度合并。
- 输出前统一 `int(i)`，确保无 `np.int64(...)`。

`scripts/bertalign_runner.py` 已按上述思路实现。
